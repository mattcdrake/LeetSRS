# Test suite reduction

Follow-up to [#583](https://github.com/mattcdrake/LeetSRS/issues/583) in [#577](https://github.com/mattcdrake/LeetSRS/pull/577).

The follow-up baseline is commit `33bad32`: **421 expanded cases in 52 files**. The result is **303 cases in 46 files**, a net reduction of **118**. Parameterized rows count individually. The original PR began at 482 cases in 54 files; the combined reduction is 179 cases and eight files.

The issue's approximately 150 additional removals was an estimate, not a quota. Retained settings, startup, catalog, queue, and query tests cover distinct behavior: atomic settings publication, no-op writes, initialization coordination, synchronous transaction failure versus asynchronous abort, catalog batching, missing catalog records, precise due-time filtering, subscriptions, and stale reads. Removing these merely to reach 270 cases would trade away sharper regression protection.

Production code, test infrastructure, configuration, and coverage requirements are unchanged. Authorization, stale-sync and lost-write races, content disposal, every migration version, and calendar boundaries remain covered.

## Replacement workflows

- [Review workflows](../popup/views/home/__tests__/review-workflow.test.tsx) use real components, query hooks, registered background commands, catalog, and validated browser storage. They exercise draft/collapse/reopen, failed save/retry, saving while collapsed, card-list reopening, failed review/retry, persisted scheduling/activity, next-card advancement, search and pause filters, pause/resume, confirmed removal, file import, cancelled/failed/successful reset, and both DST transitions. Only browser boundaries, time, and storage failures are controlled.
- [Gist workflow](../popup/views/settings/__tests__/gist-workflow.test.tsx) uses the real service with mocked GitHub responses and browser permissions. It begins with an authorized account, connects an existing backup, pauses sync, cancels a change, fails and retries creation, checks pending controls, and signs out while preserving learning data. The separate authorization and gesture-coordination suites remain.
- [Document transfers](../background/__tests__/document-transfer.test.ts) import versions 0–11 through the registered service, check the complete persisted document and retained connection, and reject invalid JSON, a malformed current card, and a future version before any write, followed by a successful edit.
- [ReviewQueue ordering tests](../popup/views/home/__tests__/ReviewQueue.test.tsx) retain controlled command/refresh races but now render the real children. The pending-action test opens the real note editor and actions panel to check disabled controls and duplicate prevention.
