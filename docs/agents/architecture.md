# Architecture reference

Ownership and implementation constraints. Keep this reference aligned with authorized design changes; historical decisions live in ADRs.

## Ownership and dependencies

These rules apply to runtime and type-only imports:

- `entrypoints/` owns WXT registration and mounting files, including popup HTML and React bootstrap. Background registration invokes `background/handlers.ts` synchronously.
- `popup/` owns React UI, query hooks, cache invalidation, and popup-specific interactions. `content/` owns content UI, mounting, and lifecycle; `content/rating-actions.ts` coordinates problem lookup and background RPC.
- `domain/` owns application models and schemas, current document invariants, scheduling, review days, settings, language, and Gist conflict policy. Pass explicit inputs; keep browser, storage, background, messaging, and translation-catalog dependencies out. `ts-fsrs` is allowed.
- `background/` owns named write workflows, edit clocks, FSRS lifetime, local-save coordination, sync execution, and message/alarm handlers. It composes domain rules, data, and integrations without cycles.
- `data/` owns current storage keys, validated readers/writer, read queries, and storage subscriptions. `data/legacy/` owns historical schemas, backup parsing/conversions, and the startup bridge invoked by background initialization. Data modules must not depend on background workflows or UI.
- Popup query hooks read validated storage directly. `data/learning-queries.ts` shares settings reads with background; `domain/review.ts` owns the complete pure review-queue policy; single-use projections and export serialization live in query functions. Time-derived reads capture one document and time and call pure domain policy. Current readers remain independent of background write initialization, FSRS initialization, and historical conversions.
- Review-queue Problem links carry a one-opening editor-reset authorization only when the resolved setting is enabled. The native external-link behavior remains responsible for mouse and keyboard navigation; Cards-list links never authorize reset.
- `integrations/` owns GitHub requests, browser messaging and language detection, and LeetCode DOM/GraphQL access. It must not depend on background workflows or UI. Shared message contracts and transport remain safe to import from popup/content without loading background handlers or write initialization.
- `i18n/` owns translation catalogs and the `Translations` type. It may import the domain language type, but has no browser, storage, service, or UI dependencies. Settings policy uses the domain language registry without loading dictionaries.
- Popup and content writes use `integrations/browser/messages.ts`; background owns learning-data writes. Their persisted-data reads use data modules directly. Content translations use `data/translations.ts`.
- The popup owns permissions, active-tab inspection, and banner dismissal state. Permission requests originate from user interactions.

## Background execution

Before changing background commands or sync execution, read [ADR-0005](../adr/0005-direct-whole-dataset-gist-sync.md).

- RPC contracts and transport belong in `integrations/browser/messages.ts`.
- `background/handlers.ts` registers explicit typed handlers, validates message payloads, awaits startup, and invokes named workflows. Local saves run independently of network and badge work; overlapping local writes are an accepted limitation.
- `background/gist-sync.ts` owns one enabled/disabled whole-document sync operation. Successful connection setup enables and starts sync. Startup, successful local edits, enabling, and the minute alarm also call it; overlapping calls share one in-flight promise without queuing a follow-up. Download before reading current local data. A generation change stops document sync started before an import, reset, or connection change from applying a stale result. Already-issued writes and uploads remain subject to the accepted narrow races. Connection setup and toggles use direct last-completed-write-wins persistence rather than their own lifecycle coordination.
- Popup and content lifecycle do not trigger sync or block edits. The settings UI has no manual sync action.
- Badge refresh reacts independently to document changes, a one-shot alarm for the next unpaused card due time, and the minute tick. Derive its count and next due time from one document snapshot; preserve an already scheduled alarm when the due time is unchanged. Its failures are best effort, including at startup.
- Register message and alarm listeners synchronously during startup. Handlers wait for startup readiness before accessing storage. UI readers display valid current documents directly; missing or older documents await `waitForInitialization` before rereading. Initialization and conversions remain background-owned, and failed or invalid documents surface errors instead of empty defaults.

## Content UI lifecycle

- Mount controls and toasts with WXT `createShadowRootUi` and `cssInjectionMode: 'ui'`. Keep portals inside the shadow root, using the top layer to avoid toolbar clipping. Detect themes from LeetCode's page classes.
- WXT removal unmounts React. Context invalidation also disconnects the toolbar observer and disposes the editor-reset workflow, which stays outside React. Components clean up subscriptions and timers on unmount.
- `content/editor-reset.ts` consumes and removes a review-queue authorization from the destination URL once, then owns reset-control discovery, reset and recognized-confirmation clicks, notification timing, cancellation, and timer cleanup. Its work remains local to that destination opening and stops on navigation or content disposal; ordinary browsing, refresh, and history restoration do not start it.

## Storage, backup, and sync

[ADR-0003](../adr/0003-single-document-learning-data.md) records the single-document design. The document is authoritative at runtime. The superseded migration lifecycle and collection/settings persistence wrappers have been removed; historical compatibility lives in the startup bridge and pure document conversions.

- One browser-local document owns its schema version, modification timestamp, slug-keyed cards with embedded notes, daily statistics, and stored settings overrides. Card timestamps use epoch milliseconds; `dataUpdatedAt` is an optional timestamp string, and statistics are keyed by local `YYYY-MM-DD` dates. Missing settings retain normal defaults, including browser-language detection.
- The v7 conversion replaces the legacy every-Problem and due-review editor-reset settings with one review-queue-opening setting. An explicit new value wins; otherwise either enabled legacy mode enables it, while both disabled or absent leave it disabled.
- The v8 conversion removes the redundant date, total-review, and reviewed-card fields from persisted daily statistics. History projections derive those values from the date key, new-card count, and rating breakdown while retaining the persisted streak needed across compacted history.
- Domain owns current schemas and explicit-input policy. Named local workflows in `background/learning.ts` prepare complete changes and pass their captured edit time to a private shared save helper. This shared save path prepares the timestamp, calls the writer for final completed-document validation and one write, then requests automatic sync without awaiting GitHub. No-op and failed writes do not request sync. Command payload schemas own early input validation and settings-update normalization; workflows consume those parsed inputs without repeating those checks. Reviews commit cards, statistics, and their edit timestamp together; queue calculations use one captured document and time. Keep normal operations behind startup readiness. Sync uses storage/conversion functions directly, keeping the local-save-to-sync dependency acyclic.
- `data/learning-document.ts` owns current-document reads, the shared required-document check, and validating replacement through the shared storage keys. `data/legacy/learning-document-conversions.ts` owns backup parsing and pure version-conversion orchestration shared by startup, import, and Gist pull. `data/legacy/document-conversions/` owns the frozen historical contracts and individual conversions. Every numbered conversion defines a frozen output schema and must not alias or import the evolving current document schema; the orchestrator validates the final result against the current schema. Preserve supported historical versions and their meaning, frozen historical data contracts, and precedence rules. Validate historical input before stripping extras and validate the current result. Keep browser storage, clocks, per-step loaders/savers/cleanup, physical-layout modules, and intermediate completion writes out of the conversion sequence.
- One startup bridge gathers scattered legacy values only when the new document is absent. Prepare and validate before writing the complete document and its version. After success the document is authoritative; cleanup failure must not trigger re-import, and corrupt or future documents must not fall back to stale legacy keys. Preserve credentials and already-combined connection values over retained legacy fields.
- File backups and Gist payloads use the document representation. Import validates and converts before one replacement, preserves the imported timestamp, and clears omitted notes/settings through replacement. Retain legacy backup timestamp fallback without treating conversion as a learner edit.
- The PAT, Gist ID, and syncing setting remain a separate browser-synced connection. Sync status stays local. Import leaves both untouched; explicit Reset All Data also clears the connection, retained legacy connection keys, and local status.
- Whole-dataset conflict resolution remains [ADR-0002](../adr/0002-whole-dataset-gist-sync.md). Reject unsupported remote formats before replacing data or writing a Gist. All browsers sharing a Gist must update before resuming sync; the transition does not support dual writes or old and new clients syncing together.
- Preserve supported learning data and meaningful failure behavior. Keep obsolete migration/persistence machinery and sequencing-only tests out of the runtime and test suite. A single document does not imply a transaction across connection/status writes or a crash-recovery framework.
