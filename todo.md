## Acceptance criteria

- Each behavioral fix has a demonstrated failing regression test and Matt's explicit go-ahead before implementation; mechanical refactors preserve existing behavior.
- Unparseable or unpreparable payloads leave existing storage untouched. After migration, any invalid individual record or relationship rejects the entire import before replacement. Valid empty collections remain valid replacement imports.
- Valid imports retain metadata, schedules, pause state, domain information, and associated notes. Card keys agree with slugs, stats keys agree with dates, IDs are unique, and every note references an imported card.
- Startup and legacy imports use the same ordered schema transformations. Preparation does not write storage; failed startup migration blocks dependent operations and does not advance the failed version.
- Current export/Gist payload compatibility, PAT preservation, legacy settings aliases, and imported update timestamps are retained. Domain policy does not import storage types. Catalog validation and transactional rollback after persistence starts are outside this issue.
- Focused regression tests fail for the intended reason at each Step 1 checkpoint and pass after its Step 2. Final `npm run check` and the manual scenarios above pass; run `npm test` and `npm run check` with elevated sandbox permissions as required by repository instructions.
