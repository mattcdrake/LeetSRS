# Manual verification: GitHub authentication and Gist sync

Issue: [#295](https://github.com/mattcdrake/LeetSRS/issues/295) · Parent: [#298](https://github.com/mattcdrake/LeetSRS/issues/298)

- [ ] Load the current extension build in a test browser profile. Use disposable learning data and Gists, a valid PAT with Gist access, and the extension service worker's Network and storage tools to observe requests and saved fields.
- [ ] Open Settings → GitHub Gist Sync. With an empty PAT, verify validation is disabled. Enter an invalid PAT and validate: the existing invalid-token feedback appears and saved credentials stay unchanged. Validate a valid PAT: success includes the username and the PAT is saved.
- [ ] Enter a nonexistent Gist ID, then an existing Gist without `leetsrs-backup.json`: validation fails without replacing the saved destination. Validate an existing Gist containing that file: validation succeeds and saves its ID. Confirm validation uses the entered PAT, including when it differs from the saved PAT.
- [ ] Click Create New Gist. Verify GitHub creates a secret/private Gist with the localized description and `leetsrs-backup.json`. Its content matches a backup export, contains no PAT, and the returned ID, sync time, and push direction are saved.
- [ ] Close and reopen the popup. Verify the saved PAT, Gist ID, automatic-sync switch, and last-sync status are restored. Enable automatic sync: the setting persists and a sync starts immediately. Disable it again for the next checks.
- [ ] Make a local learning-data edit, then click Sync Now. Verify a push updates the Gist with that edit and records the push direction and completion time. Run Sync Now again without edits: verify no upload or import occurs, the sync time advances, and the direction remains unchanged.
- [ ] Edit a test note in the remote backup JSON and set its `dataUpdatedAt` later than the local value. Click Sync Now: verify the remote note is imported, the saved PAT survives, and status records a pull. Repeat Sync Now: verify a no-change result.
- [ ] Temporarily block GitHub requests using the Network tools and click Sync Now. Verify the existing error feedback appears and the busy state clears. Unblock requests and retry: verify sync succeeds and the previous error clears.
- [ ] Enable automatic sync, make a local edit, and leave the popup closed for at least one one-minute alarm cycle. Verify the edit reaches the Gist. Disable sync, make another edit, and wait again: verify no automatic Gist request occurs and badge refresh still works.
- [ ] In extension test-profile storage, keep `leetsrs:gistSyncEnabled` true and separately remove `leetsrs:githubPat` and `leetsrs:gistId` from sync storage, restoring each before the next case. Wait for an alarm in each case: verify no GitHub requests occur and badge refresh still works. Restore the complete connection afterward.
- [ ] Export the test data, change a local note, and import the export. Verify the exported JSON contains no PAT, restores the exported data/settings/Gist configuration, and preserves the current PAT. Add a dummy `githubPat` field to the imported `data.gistSync` object and repeat: verify it is ignored. Repeat with no stored PAT and with an empty stored PAT: neither restores a credential from the file.
- [ ] Restore a test connection, then reset all data through Settings. Reopen the popup and inspect storage: learning data, credentials, Gist configuration, and sync status are cleared. Verify the next alarm skips GitHub requests.
