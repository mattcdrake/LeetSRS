## Acceptance criteria

- Runtime-validated domain types are inferred from shared, composable schemas independent of browser/storage code; internal-only types remain TypeScript, and redundant models/validators are removed.
- Every payload-bearing background message rejects malformed input before handlers or mutation side effects. Valid requests retain startup and queue behavior.
- Malformed GraphQL responses return null; valid regional titles and translated-title fallback remain correct.
- Storage reads validate known fields and strip unknown fields, including nested fields, while preserving missing-data and settings defaults. Invalid records produce ordinary parse errors.
- Settings error messages, own-property handling, undefined-as-omitted updates, browser defaults, and Gist optional/null semantics remain compatible, and prototype names are rejected as languages. Notes must not exceed 500 characters at save, storage, or import boundaries.
- Supported backups retain migrations, timestamp compatibility, relationship validation, and PAT handling; rejected imports do not replace local data.
- Focused behavioral regression tests and `npm run check` pass; the manual scenarios above pass. These checks are required implementation validation, not results of this planning task.
