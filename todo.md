# Separate GitHub authentication from Gist setup and sync

Issue: [#295](https://github.com/mattcdrake/LeetSRS/issues/295) · Parent: [#298](https://github.com/mattcdrake/LeetSRS/issues/298)

Step 1 of 4: change ownership while preserving behavior. Sync execution cleanup, the new setup UI, sync/backup separation, and OAuth belong to later work.

## Acceptance criteria

- Authentication owns credential access, PAT validation, and client acquisition; Gist setup owns destination configuration and consumes an authenticated client, as does sync. Internal callers import from the owning modules; `github-sync.ts` has no auth/setup re-exports or forwarding compatibility adapters. Infrastructure remains independent of services, and service dependencies remain acyclic.
- Existing PAT connections, popup interactions, RPC inputs/results, errors, sync policy, queue behavior, and persistence order remain compatible, including partial failures and untrimmed validation inputs.
- Storage keys, schema, backup and Gist payloads remain unchanged. Import preserves the existing truthy PAT, standalone reset removes credentials, and exports omit credentials.
- Relevant auth, setup, sync, background, and import/export regression tests and `npm run check` pass; the manual scenarios above produce the expected observations. Run tests and `npm run check` with the repository-required sandbox escalation.
